## 1. 技术选型与纯单机适配规则

### 1.1 引擎与架构
- **引擎**：**Cocos Creator 3.8 LTS（TypeScript）**
  - 理由：官方原生支持一键构建发布抖音小游戏，包体轻量（适配抖音首包 4MB / 分包 20MB 限制），对 2.5D 透视相机、骨骼动画（Spine）和轻量 3D 均成熟稳定。
- **存档方案**：**纯单机本地存储**（`tt.setStorageSync` + 本地 JSON 存档，无后端服务器）。

### 1.2 纯单机带来的设计调整（重要）
| 系统 | 原云端设想 | 纯单机落地调整 |
|---|---|---|
| **饱腹度防改时间** | 服务端时间戳校验 | 读取本地时间，记录 `lastTimestamp`；若检测到系统时间倒流（`now < lastTimestamp`），直接忽略本次时间差，**不回退也不扣除**，对治愈向单机已足够 |
| **好友串门** | 拉取真实好友院子布局 | 改为 **「拜访 NPC 猫咪达人院子」**（内置 5–8 套不同主题示范院子，每天可去撸猫领少量金币 5 次），既保留串门体验又无需后端 |
| **排行榜** | 全服/好友周榜 | 使用抖音小游戏自带 **开放数据域（Open Data Context）**，无需自建服务器即可在本地展示好友闯关星数/每日一谜排行 |
| **防丢档** | 云存档 | 在设置里提供 **「导出/导入存档码」**（压缩加密字符串），方便玩家换机或清缓存前手动备份 |

## 3. 经济系统调优（放慢金币节奏）⚙️

为了让阿狸成为真正有分量的中长线追求，**整体下调金币产出，同时降低日常猫粮售价以保证每天能正常喂猫**：

### 3.1 每日金币产出（普通玩家模型）
| 来源 | v0.2 原值 | v0.3 调整值 | 调整理由 |
|---|---|---|---|
| **离线家园产出** | 5 × 亲密度等级/小时 | **2 × 亲密度等级/小时**（上限 8 小时） | 降低被动挂机膨胀；3 只平均 Lv3 的猫每天收 2 次约 **288 金币** |
| **闯关通关** | 首通 40 / 重复 15 | **首通 25 / 重复 8**（每日重复上限 80） | 防止靠重刷简单关快速刷爆金币 |
| **每日心愿 + 访客** | ~300 | **~150** | 作为日常稳定补充 |
| **合计日均产出** | ~1500 | **~500–650**（纯佛系家园约 **350–450**） | 大幅放慢积累速度 |

### 3.2 每日金币消耗
| 消耗项 | v0.2 原值 | v0.3 调整值 | 设计意图 |
|---|---|---|---|
| **猫粮**（+20 亲密 / +20 饱腹） | 50 金币 | **30 金币** | 保证金币慢了以后，玩家依然喂得起猫，不被卡养成 |
| **猫条**（+45 亲密 / +15 饱腹） | 150 金币 | **100 金币** | 高性价比小零食 |
| **家具装扮** | 500–3000 | **300–1,800** | 让玩家在"买家具装扮"与"攒钱买阿狸"之间做选择 |
| **商店猫咪：阿狸** | 8,000 | **12,000** | 正常每天喂猫 + 偶尔买家具，净攒约 300–400/天 → **约 20–30 天**攒够；专心攒钱不买家具则 **约 16–20 天** |

- **亲密度升级送金币**也同步下调为 `等级 × 100`（原 `× 200`），避免多猫同时升级一次性放出大量金币冲垮阿狸定价。

## 4. 激励广告点位（汤姆 10 次解锁）
沿用自愿激励模式（无强制插屏）：
- 解谜提示（每关首次免费，后续看广告）、跳过关卡（每日 3 次）、结算双倍（每日 5 次）、离线翻倍（每日 3 次）、加个餐（每只猫每日 1 次，饱腹度 −30）、每日罐头 / 家具商店刷新（各 1 次）。
- 所有激励广告均计入 **汤姆（10 次）** 的解锁进度。
